## 1. 概述

阶段五实现了剖面块的变更检测与更新机制。每次生成剖面时，系统将各楼层的几何指纹（SHA256 哈希）存入块的 XData；当平面图修改后，`CheckSectionUpdates` 命令重新计算哈希并与快照比对，在非模态对话框中展示哪些剖面需要更新，支持选中更新和全部更新。

## 3. 核心类详解

### 3.1 `SectionSnapshot` — 快照数据模型

**字段**:
- `SectionId`: 唯一标识（GUID）
- `BlockName`: 块名称（如 `MK_剖面_F1_F2_20260416T143022`）
- `CutLineStart/End`: 原始剖切线坐标（用于重新生成）
- `InsertionPoint`: 块插入点（用于重新生成）
- `ViewDepth`: 视图深度
- `TotalHeight`: 总高度
- `FloorSnapshots`: 各楼层快照列表

**`FloorSnapshot` 字段**:
- `FloorName`: 楼层名称
- `GeometryHash`: 该层构件的 SHA256 哈希（前 16 位）
- `ElementCount`: 构件数量

### 3.2 `XDataSnapshotRepository` — XData 快照仓储

**存储格式**（应用名 `MK_SectionSnapshot_V2`）:
```
[AppName]  MK_SectionSnapshot_V2
[String]   <JSON 序列化的 SectionSnapshot>
```

**关键方法**:
- `Save(blockHandle, snapshot)`: 序列化为 JSON 写入块 XData
- `Load(blockHandle)`: 从块 XData 读取并反序列化
- `FindAllSectionBlockHandles()`: 扫描模型空间，返回所有含快照的块句柄

### 3.3 `CheckSectionUpdatesUseCase` — 变更检测用例

**算法**:
```
foreach blockHandle in FindAllSectionBlockHandles():
    snapshot = Load(blockHandle)
    if snapshot == null → status = Unknown
    else:
        foreach floorSnap in snapshot.FloorSnapshots:
            if floor not in config → skip
            currentHash = hasher.ComputeHash(recognizer.RecognizeElements(...))
            if currentHash != floorSnap.GeometryHash → outdatedFloors.Add(floor)
        status = outdatedFloors.Count > 0 ? Outdated : UpToDate
```

### 3.4 `UpdateSectionUseCase` — 单剖面更新用例

**流程**:
1. 从快照读取原剖切线坐标和插入点
2. 调用 `IGenerateSectionUseCase.Execute()` 重新生成
3. 调用 `IBlockEraseService.EraseBlock()` 删除旧块

### 3.5 `SectionUpdateDialog` — 变更检测对话框

**功能**:
- 非模态显示（`ShowModelessWindow`）
- 列表展示所有剖面的状态（✓ 最新 / ⚠ 需更新 / ? 未知）
- 支持多选、全选/全不选
- "更新选中"：只更新勾选的剖面
- "全部更新"：更新所有 Outdated 状态的剖面
- "刷新"：重新执行检测

## 7. 已知限制

1. **检测时使用空剖切线**：`CheckSectionUpdatesUseCase` 当前用空剖切线调用识别器，实际应从快照中读取原剖切线。阶段六双向定位完成后可改进。
2. **XData 存储大小**：JSON 快照大小受 AutoCAD XData 限制（每条 1000 字节），楼层数量多时需分段存储（当前版本未处理）。
3. **非模态对话框线程**：`SectionUpdateDialog` 在 UI 线程执行更新，大量剖面时可能阻塞界面，后续可改为后台线程。
