## 2. 架构复核结论

### 2.1 通过项

- 项目引用关系符合 [architecture.md](./architecture.md) 中的分层约束：
  - `SectionGenerator.App` 仅依赖 `Core` 与抽象接口
  - `SectionGenerator.Infrastructure` 实现 `App.Abstractions`
  - `SectionGenerator.Plugin` 负责命令、WPF、AutoCAD 交互
- `App/Core` 层未引入 `Autodesk.AutoCAD.*` 或 `System.Windows.*`
- 第六阶段新增的双向定位能力继续沿用“App 定义接口，Infrastructure 提供实现”的模式：
  - `ISectionReferenceRepository`
  - `IEntityNavigationService`
- 第六阶段命令入口仍全部留在 `Plugin/Commands`，未把宿主逻辑下沉到用例层

### 2.2 本轮修复项

1. 去除工具箱 UI 对 `Startup.CommandRegistry` 静态状态的直接依赖  
   处理方式：
   - `SectionToolboxControl` 改为显示静态状态文案
   - `Startup` 中删除多余的全局 `CommandRegistry` 暴露

2. 统一“楼层对齐后的剖切线”在生成与更新检测中的使用  
   处理方式：
   - 新增 `FloorSectionLineTransformer`
   - `GenerateSectionUseCase` 与 `CheckSectionUpdatesUseCase` 统一通过该帮助类计算楼层对齐后的剖切线

3. 修正识别器对剖切线范围的忽略  
   处理方式：
   - `LayerBasedElementRecognizer` 仅返回与剖切线相交的构件
   - 这样每层快照哈希与更新检测不再默认扫描整张图中的所有构件

4. 补齐 AutoCAD 宿主入口与命令桥接  
   处理方式：
   - `Bootstrap` 新增 `IExtensionApplication` 入口，确保 `NETLOAD` 后自动初始化
   - `SectionGenerator.Plugin` 新增命令桥接层，避免 AutoCAD 直接实例化带依赖的命令类
   - 新增 `SectionSelfTest` 命令，供 `accoreconsole` 做最小宿主自检

5. 补齐插件运行时依赖分发  
   处理方式：
   - 插件项目在构建后自动复制 `Microsoft.Extensions.*` 运行时程序集到输出目录
   - 修复仅能“编译通过”但 AutoCAD 宿主中无法正常解析依赖的问题

### 2.3 当前残留限制

- `viewDepth` 目前已参与命令输入、快照存储和日志记录，但“看线/投影线”的完整几何表现仍未完全落地，仍需在 AutoCAD 宿主内做最终行为确认
- `accoreconsole` 可用于非交互烟测，但 `FloorConfig`、`ShowToolbox`、`CheckSectionUpdates` 等 UI/交互命令仍需在 `acad.exe` 中人工验收
- `dotnet test` 仍受当前机器 NuGet/测试依赖环境影响，尚未在本机重新刷新阶段七后的最新统计
