## 用户日志结构化规范

以下为面向最终用户的日志输出规范，聚焦于用户在 AutoCAD 命令行、工具箱面板及日志文件中可见的提示信息。目标：**清晰、简洁、可操作**，避免技术堆栈细节暴露。

---

### 1. 用户日志输出目标

| 输出位置 | 用途 | 内容要求 |
|:---|:---|:---|
| **AutoCAD 命令行** | 实时反馈操作状态、进度、错误提示 | 单行简短消息，避免刷屏 |
| **工具箱状态栏/提示区** | 辅助信息（如当前配置、选中数量） | 极简文本 |
| **日志文件**（`MetroToolKits_User.log`） | 详细操作记录，供用户事后排查或提交反馈 | 结构化、含时间戳和上下文 |

---

### 2. 日志级别与呈现

| 级别 | 命令行前缀 | 日志文件标记 | 用户感知 |
|:---|:---|:---|:---|
| **信息** | `[信息]` 或无前缀 | `INFO` | 正常操作提示，无干预 |
| **警告** | `[警告]` | `WARN` | 非致命问题，用户可决定是否处理 |
| **错误** | `[错误]` | `ERROR` | 操作中断，需用户注意或修正 |
| **进度** | 动态更新（如 `已完成 3/5 楼层...`） | 不写入文件 | 长时间任务的状态反馈 |

---

### 3. 各模块用户日志模板

#### 3.1 命令执行通用

| 场景 | 命令行输出示例 | 日志文件内容 |
|:---|:---|:---|
| 命令开始 | `命令: GenSection 已启动` | `[INFO] GenSection started` |
| 命令取消（用户按 ESC） | `命令已取消` | `[INFO] GenSection cancelled by user` |
| 命令完成 | `剖面生成成功，块名称: MK_剖面_主楼` | `[INFO] GenSection completed, block: MK_剖面_主楼` |
| 命令失败（可恢复错误） | `[错误] 未选择有效剖切线，请选择一条直线` | `[ERROR] Invalid section line selected` |

从 `v1.1.0-beta` 起，失败与诊断日志会附带统一上下文：

- `Code`：稳定失败码，例如 `SectionGenerator.ElementRecognition.NoRecognizedElements`
- `Stage`：失败阶段，例如 `ElementRecognition`
- `Module`：失败来源模块，例如 `GenerateSectionUseCase`
- `DiagnosticCount`：本次附带的 warning/error 数量

#### 3.2 构件识别与转换

| 场景 | 命令行输出示例 | 日志文件内容 |
|:---|:---|:---|
| 全图映射应用 | `已转换 124 个图元到标准图层` | `[INFO] Layer mapping applied: 124 entities converted` |
| 区域转换开始 | `区域转换模式，框选范围内共 8 个图层` | `[INFO] Region conversion started, 8 layers found` |
| 逐层引导提示 | `图层 [A-WALL] (5个图元) → 请指定类型 [S/M/C/B/F/D/W/T/Q/跳过]:` | 不写入文件（交互过程） |
| 转换确认 | `已为 6 个图层指定构件类型，是否应用？[是(Y)/否(N)]` | 不写入 |
| 转换应用 | `转换完成，6 个图层共 43 个图元已更新` | `[INFO] Conversion applied: 6 layers, 43 entities` |
| 转换跳过（用户选否） | `转换已放弃` | `[INFO] Conversion discarded by user` |
| 恢复备份 | `已恢复 43 个图元到原始图层` | `[INFO] Revert completed: 43 entities restored` |

#### 3.3 楼层配置

| 场景 | 命令行输出示例 | 日志文件内容 |
|:---|:---|:---|
| 加载配置 | `已加载楼层配置: 3 个楼层 (F1,F2,F3)` | `[INFO] Floor config loaded: 3 floors` |
| 配置缺失 | `[警告] 未找到楼层配置文件，将使用默认单层配置` | `[WARN] Config file missing, using defaults` |
| 对齐点拾取引导 | `请拾取楼层 F2 的三个基准点...` | 不写入 |
| 对齐点拾取完成 | `楼层 F2 对齐点已记录` | `[INFO] Alignment points set for floor F2` |

#### 3.4 剖面生成

| 场景 | 命令行输出示例 | 日志文件内容 |
|:---|:---|:---|
| 开始计算 | `正在生成剖面，处理楼层 F1...` | `[INFO] Generating section for floor F1` |
| 进度反馈（多楼层） | `已完成 F1，正在处理 F2 (2/3)...` | 不写入 |
| 生成结果 | `剖面生成成功。块名: MK_剖面_主楼_20260416T1430` | `[INFO] Section block created: MK_剖面_主楼_20260416T1430` |
| 部分楼层无构件 | `[警告] 楼层 F3 未识别到任何构件，已跳过` | `[WARN] Floor F3 has no elements, skipped` |
| 剖切线无效 | `[错误] 剖切线未穿过任何构件，请调整剖切线位置` | `[ERROR] Section line does not intersect any element` |
| 全部楼层无有效构件 | `[错误] 未识别到任何可生成剖面的构件` | `[ERROR] Code=SectionGenerator.ElementRecognition.NoRecognizedElements` |

#### 3.5 变更检测与更新

| 场景 | 命令行输出示例 | 日志文件内容 |
|:---|:---|:---|
| 检测开始 | `正在检查剖面更新状态...` | `[INFO] Checking section updates` |
| 检测结果摘要 | `共 5 个剖面，其中 2 个需要更新` | `[INFO] 5 sections checked, 2 outdated` |
| 批量更新触发 | `正在更新 2 个剖面...` | `[INFO] Batch updating 2 sections` |
| 批量更新完成 | `更新完成：成功 2 个，失败 0 个` | `[INFO] Batch update done: 2 succeeded, 0 failed` |
| 单剖面更新 | `剖面 [MK_剖面_主楼] 已更新` | `[INFO] Section updated: MK_剖面_主楼` |
| 更新失败（剖切线丢失） | `[错误] 剖面 [MK_剖面_主楼] 的原始剖切线已不存在，请手动重新生成` | `[ERROR] Original section line lost for MK_剖面_主楼` |

#### 3.6 双向定位

| 场景 | 命令行输出示例 | 日志文件内容 |
|:---|:---|:---|
| 平面→剖面查询结果 | `共找到 2 个剖面引用了该墙体` | `[INFO] Found 2 sections referencing element {Handle}` |
| 剖面→平面定位 | `已定位到源构件（结构墙）` | `[INFO] Located source element: StructuralWall {Handle}` |
| 无关联剖面/构件 | `未找到关联的剖面` | `[INFO] No related sections found` |

### 4. 日志文件格式规范

日志文件采用纯文本格式，每行一条 JSON 结构，便于程序解析。

**示例**：

```json
{"time":"2026-04-16T14:30:22","level":"INFO","msg":"GenSection started","user":"DOMAIN\\Username"}
{"time":"2026-04-16T14:30:25","level":"INFO","msg":"Section block created","block":"MK_剖面_主楼_20260416T1430","floors":3,"elapsedMs":2850}
{"time":"2026-04-16T14:32:10","level":"WARN","msg":"Floor F3 has no elements, skipped"}
{"time":"2026-04-21T18:30:08","level":"ERROR","category":"MetroToolKits.Bootstrap.Logging.OperationFeedbackPresenter","msg":"命令 GenSection 失败，Code=SectionGenerator.ElementRecognition.NoRecognizedElements，Category=DomainBusiness，Stage=ElementRecognition，Module=GenerateSectionUseCase，Diagnostics=3","CommandName":"GenSection","Code":"SectionGenerator.ElementRecognition.NoRecognizedElements","Stage":"ElementRecognition","Module":"GenerateSectionUseCase","DiagnosticCount":3}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `time` | ISO 8601 | 日志时间戳 |
| `level` | string | `INFO` / `WARN` / `ERROR` |
| `msg` | string | 简短描述 |
| 其他 | 任意 | 上下文数据（如 `block`、`floors`、`elapsedMs`） |

---

### 5. 命令行输出原则

- **单行原则**：每条消息尽量不超过一行，避免折叠。
- **无技术细节**：不显示堆栈跟踪、内部异常类名。错误信息仅显示用户可执行的建议。
- **进度动态刷新**：使用 `Editor.WriteMessage` 配合 `\r` 或 `Editor.StatusBar.Progress` 实现原地刷新。
- **静默模式支持**：工具箱界面中可提供“减少提示”选项，仅保留警告和错误。

---

### 6. 用户日志配置切换

用户可通过工具箱“设置”页调整日志输出详细程度：

| 选项 | 效果 |
|:---|:---|
| **详细** | 命令行显示进度及结果摘要，日志文件记录所有 INFO 及以上事件 |
| **简洁**（默认） | 命令行仅显示错误和关键结果（如“剖面已生成”），日志文件记录 INFO+WARN+ERROR |
| **仅错误** | 命令行仅显示错误，日志文件仅记录 ERROR |

配置保存至 `appsettings.json` 中的 `UserLogging` 节区。
