## 1. 背景与目标

### 1.1 背景

项目实际代码与 `README.md` 中定义的架构存在若干偏离，部分偏离属于功能自然扩展（合理），部分偏离违反了依赖倒置原则（需修复）。为保持架构一致性与长期可维护性，需系统性地进行纠偏。

### 1.2 目标

- **文档与代码对齐**：更新 `README.md` 使其准确反映当前项目结构。
- **修复架构违规**：消除跨层对具体实现的直接依赖，遵循依赖倒置原则。
- **消除冗余结构**：简化项目引用层次，降低维护成本。
- **保证功能不变**：所有现有功能、单元测试 100% 通过。

## 3. 逐项纠偏详细方案

### 3.1 D1：`Foundation.Building` 未在架构中定义

**现状**：项目实际存在 `MetroToolKits.Foundation.Building` 项目，包含 `BuildingElement`、`Wall`、`Slab` 等构件模型，被 `Core` 和 `Infrastructure` 引用。

**行动**：

- [ ] 更新 `README.md` 架构总览图，在 `Shared` 层增加 `Foundation.Building` 模块。
- [ ] 在分层职责表中新增一行：

| 层级 | 项目 | 职责 | 依赖规则 |
|:---|:---|:---|:---|
| 通用工具层 | `Foundation.Building` | 建筑构件领域模型及识别接口 | `Foundation.Core` |

- [ ] 更新 Core 层依赖规则：`依赖 Foundation.Core 和 Foundation.Building`。

---

### 3.2 D2：`CadAdapter` 层未在架构中定义

**现状**：存在 `MetroToolKits.SectionGenerator.CadAdapter` 项目，仅包含 `CadDrawingService.cs`（实现 `IDrawingService` 接口）。

**分析**：按架构设计，`IDrawingService` 接口定义在 `App.Abstractions`，实现应放在 `Infrastructure`。独立项目增加编译依赖且无额外收益。

**方案选择**：✅ **合并至 Infrastructure**

**行动**：

- [ ] 将 `CadDrawingService.cs` 移动到 `MetroToolKits.SectionGenerator.Infrastructure/Services/`。
- [ ] 更新 `Infrastructure.csproj`，移除对 `CadAdapter` 的项目引用。
- [ ] 更新 `Plugin.csproj`，移除对 `CadAdapter` 的项目引用。
- [ ] 删除 `MetroToolKits.SectionGenerator.CadAdapter` 项目文件夹。
- [ ] 从解决方案中移除该项目。
- [ ] 更新 `Bootstrap/Startup.cs` 中的 DI 注册，将 `IDrawingService` 的实现改为 `CadDrawingService`（路径调整）。

---

### 3.3 D3：App 层直接依赖 `Bootstrap.Logging.UserLogger` 具体类（高优先级）

**现状**：

```csharp
// GenerateSectionUseCase.cs
using MetroToolKits.Bootstrap.Logging;
...
private readonly UserLogger _userLogger;
```

**问题**：违反依赖倒置原则，App 层与 Bootstrap 层产生双向耦合。

**行动**：

- [ ] 在 `MetroToolKits.SectionGenerator.App/Abstractions/` 中新建接口文件 `IUserLogger.cs`：

```csharp
namespace MetroToolKits.SectionGenerator.App.Abstractions
{
    public interface IUserLogger
    {
        void Info(string message);
        void Warning(string message);
        void Error(string message);
        void Progress(string message);
    }
}
```

- [ ] 修改 `Bootstrap/Logging/UserLogger.cs`，实现该接口：

```csharp
using MetroToolKits.SectionGenerator.App.Abstractions;

public class UserLogger : IUserLogger { ... }
```

- [ ] 修改 `GenerateSectionUseCase.cs`、`UpdateSectionUseCase.cs`、`CheckSectionUpdatesUseCase.cs`，将字段类型改为 `IUserLogger`，并移除 `using MetroToolKits.Bootstrap.Logging;`。
- [ ] 在 `Bootstrap/Startup.cs` 中注册服务：

```csharp
services.AddSingleton<IUserLogger, UserLogger>();
```

- [ ] 编译验证，运行全部单元测试。

---

### 3.4 D4：Core 层依赖 `Foundation.Building`

**分析**：`Foundation.Building` 是纯领域模型，无 AutoCAD 依赖，Core 引用它不破坏领域纯净性。

**行动**：

- [ ] 在 `README.md` 的“分层职责说明”中，将 Core 层依赖规则改为：`依赖 Foundation.Core 和 Foundation.Building`。

---

### 3.5 D5：Infrastructure 直接依赖 Core 层 DTO

**现状**：`XDataSnapshotRepository` 使用 `SectionSnapshot`、`FloorSnapshot`，这些类定义在 `Core` 中。

**分析**：这些 DTO 是 Core 算法的输出，Infrastructure 仅负责持久化，不包含 AutoCAD 依赖。按严格分层应移至 `App.Abstractions.Models`，但移动成本较高且实际无危害。

**行动**：

- [ ] 在 `README.md` 中增加说明：“Core 层允许定义纯数据结构 DTO（如 `SectionSnapshot`），供 Infrastructure 层读写使用，以降低跨层传递复杂度。”
- [ ] 暂不调整代码。

## 6. 风险与回滚

### 6.1 风险

- **编译中断**：接口提取可能导致引用缺失，需仔细更新所有调用点。
- **DI 容器注册遗漏**：新接口若未注册，运行时将抛出 `NullReferenceException`。

### 6.2 回滚方案

- 所有代码修改在独立分支进行，合并前通过 PR 审查。
- 若合并后发现问题，可 revert 提交并重新分析。

### 8.2 分层职责表（更新）

| 层级 | 项目 | 职责 | 依赖规则 |
|:---|:---|:---|:---|
| **通用工具层** | `Foundation.Core` | 纯数学/几何算法 | 无 |

| | `Foundation.Building` | 建筑构件领域模型（`BuildingElement` 等） | `Foundation.Core` |
